Happy Corporate Coder

Run Claude Code or Codex on your workstation and control it from your phone, through a server and sign-in that your organization hosts.

Source on GitHub Deploy the server @happycc/cli on npm

Built on Happy Coder

happycc is a fork of Happy Coder (slopus/happy), an open-source mobile client for Claude Code and Codex. The CLI, the mobile and web app, and the relay server come from that project.

Upstream now puts its work into a new desktop app and its own agent runtime (happy.engineering). happycc keeps the original model: the vendor's own agent runs on your workstation, and your phone is the remote.

What it does

  • Start happycc in a terminal where you would start claude. The session also shows in the app.
  • From your phone or browser, read the conversation, send messages, answer permission prompts and stop the agent.
  • Claude Code, Codex and Agent Client Protocol agents run as their vendors built them, with their own tools and permission checks.

What is different for organizations

Areahappycc
Sign-inYour OIDC identity provider. No QR pairing. An optional authorization webhook decides which users may use the app, the web app and the agent tool.
HostingYou run the server and build the apps. Nothing calls upstream's servers. The CLI and the apps have no default server.
KeysThe server holds the encryption keys (server-managed, not end-to-end). Your organization can read stored content, as it can with its other systems.
SessionsWorkstation only. The background daemon is off, so the app cannot start sessions or run anything the user did not start at the workstation.
Remote controlThe app cannot raise a session's permission mode. It can run only a fixed list of commands, and it cannot write files or send attachments. The server checks that each session's RPC belongs to its own socket and account.
SandboxWith the sandbox on, Claude Code runs inside it whether the session is driven from the terminal or from the app.
Third partiesVoice, GitHub, analytics and push are off unless you configure them. Push notifications carry no session content.

What runs where

Workstationhappycc runs the agent. Your code stays here.
Your serverOIDC sign-in, keys, sessions, relay, optional authorization webhook.
Phone or browserThe app. No shell, no files, no new sessions.

The agent and your code stay on the workstation. The server stores sessions and passes messages between the workstation and the app. The app sends only messages, answers to permission prompts, stop, and commands from the fixed list.

Operators: deploy the server, then build the apps for your internal app store.

Developers:
